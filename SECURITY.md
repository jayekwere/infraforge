# Security policy

InfraForge 0.3.x is an offline infrastructure orchestration project, not a production-ready hosted service. AWS execution requires administrator opt-in, independent approval, an exact saved plan, a verified short-lived assumed-role session and a narrow isolated-network allowlist. Paid resource types and all Azure/GCP execution are blocked. Do not expose its API publicly or apply fictional cloud examples. For an explicitly configured AWS target, use only the separate read-only temporary-session mount described in the execution guide; never mount long-lived credentials or profiles.

Use distinct strong role tokens and an encrypted host disk. Server identity configuration, local policy/module files and tool binaries are trusted administrator inputs. Tokens stay in browser memory. Persistent request/audit documents, Terraform state and saved plans are encrypted with AES-256-GCM. Keep the key outside the data volume. Terraform needs transient plaintext in a private scratch directory; live AWS requires tmpfs. SQLite and audit hashes do not defend against a privileged filesystem administrator replacing or truncating history.

Report vulnerabilities privately through GitHub private vulnerability reporting if enabled; otherwise contact the maintainer before publishing exploit details. Do not include secrets in reports. Supported version: 0.3.x. Security changes need negative tests and complete local verification. Refer to the threat model and recovery procedures before changing approval or execution behavior.
